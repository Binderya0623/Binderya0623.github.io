Introduction to Software Engineering

Энэ хичээлээр программ хангамжийг санаанаас нь эхлээд хэрэглэгчид хүргэх хүртэлх бүх замыг туулж сурна. Улирлын турш нэг жижиг бүтээгдэхүүнийг алхам алхмаар бүтээж, долоо хоног бүр түүнийгээ илүү найдвартай, ойлгомжтой болгоно.

概要 Тойм

Энэ хичээл юуны тухай вэ?

Программ хангамжийн инженерчлэл гэдэг нь зөвхөн код бичих биш. Хэрэглэгчийн асуудлыг ойлгох, шаардлагаа тодорхой бичих, зохиомж гаргах, тест бичих, кодоо хянуулах, аюулгүй байдлыг хангах, системээ байршуулж ажиглах — энэ бүгдийг төлөвлөгөөтэй, давтагдахуйц байдлаар хийх ур чадвар юм.

Хичээлийн гол онцлог нь нэг төсөл. Та эхний долоо хоногт өөрийн бүтээгдэхүүний санааг сонгож, GitLab дээр репозитор үүсгэнэ. Дараагийн долоо хоног бүр түүн дээрээ шинэ давхарга нэмж, улирлын төгсгөлд интернетэд ажиллаж буй системээ 10 минутын илтгэлээр танилцуулна.

Хичээлийн төгсгөлд та

  • Бүтээгдэхүүний санаагаа алсын хараа, хамрах хүрээ, хэмжигдэхүйц зорилттой болгож чадна.
  • Хүлээн авах шалгууртай, спринтэд бэлэн user story бичиж, Scrum эсвэл Kanban-аар ажиллаж чадна.
  • Цэвэр, уншигдахуйц Python код бичиж, Git branch ба pull request-ээр багтай хамтран ажиллана.
  • pytest-ээр тест бичиж, coverage уншиж, CI pipeline тохируулж чадна.
  • Кодоо хянуулж, алдааг зөв боловсруулж, үндсэн аюулгүй байдлын арга хэмжээг хэрэгжүүлнэ.
  • Системээ нийтэд байршуулж, runbook, ADR зэрэг баримтуудтай болгож, төслөө танилцуулна.

学び方 Бие даан суралцах заавар

Хэрхэн суралцах вэ?

Долоо хоног бүр ижил хэмнэлээр явна. Хичээлээ тасалсан эсвэл бие даан давтаж байгаа бол энэ дарааллыг баримтлаарай.

  1. Унших

    лекцээс өмнө

    Тухайн долоо хоногийн бүлгийг уншиж, Cornell аргаар тэмдэглэл хөтөлнө. Ойлгоогүй зүйлээ асуулт болгон бичнэ.

  2. Дасгал

    60–90 минут

    Шинэ ойлголтуудаа өөрийн төсөл дээр бичгээр тайлбарлана. 1–2 хуудас хангалттай.

  3. Лаборатори

    ~135 минут

    Компьютер дээр алхам алхмаар хийх практик ажил. Өмнөх долоо хоногийн ажлаа заавал авчирна.

  4. Эргэцүүлэх

    15 минут

    Юу хийснээ, юу саад болсноо товч бичнэ. Дараагийн долоо хоногт юуг өөрөөр хийхээ шийднэ.

Эхлэхийн өмнө бэлдэх зүйлс

  • Зөөврийн компьютер 1-р долоо хоногЛабораторид долоо хоног бүр авчирна.
  • VS Code 1-р долоо хоногӨргөтгөлүүд: Python, Pylance, GitLens.
  • Python 3.11+ 1-р долоо хоногХичээлийн үндсэн хэл.
  • Git ба GitLab бүртгэл 1-р долоо хоногОюутны имэйлээрээ бүртгүүлнэ.
  • Docker Desktop 2-р долоо хоногОрчноо өөрийн компьютер дээр ажиллуулахад.
  • pip install pytest 5-р долоо хоног9-р долоо хоногоос pytest-cov, mutmut нэмэгдэнэ.

Хиймэл оюун ашиглах 3 дүрэм

Хиймэл оюун ашиглахыг зөвшөөрнө. Гэхдээ үүнийг нэрээ дурдуулалгүй хамтран зохиогч биш, хэрэгсэл гэж үзнэ.

  1. 1Зориуд ашигла. Юуны тулд ашиглаж байгаагаа мэдэж байх.
  2. 2Шалга. Гарсан үр дүнг өөрөө уншиж, ажиллуулж шалгах.
  3. 3Баримтжуул. Ямар хэрэгсэл, ямар prompt ашиглаж, юуг шалгаснаа тэмдэглэх.

用語 Нэр томьёо

Нэр томьёоны толь

Хичээлийн материал англи хэл дээр байдаг тул гол нэр томьёоны монгол тайлбарыг энд цуглуулав.

Хүлээн авах шалгуурAcceptance criterion (AC)
Story дууссан эсэхийг шалгах, ажиглаж тестлэж болох нөхцөл. «Ажиллах ёстой» гэдэг нь шалгуур биш.
Хамрах хүрээнээс гадуурх зүйлAnti-scope
Бүтээгдэхүүн юуг санаатайгаар хийхгүйг тодорхойлсон өгүүлбэрүүд. Хавсралт биш, сахилга бат.
СалбарBranch
Git репо доторх тусдаа хөгжүүлэлтийн шугам. Нэршил: feature/<богино-нэр>.
Тасралтгүй нэгтгэлContinuous Integration (CI)
Push бүрт тестийг автоматаар ажиллуулж, алдаатай кодыг нэгтгэхээс сэргийлэх процесс.
Тестийн хамралтCoverage
Тест ажиллах үед гүйцэтгэгдсэн кодын хувь. Оношлогооны хэрэгсэл, зорилго биш — чанартай адил зүйл биш.
«Дууссан»-ы тодорхойлолтDefinition of Done (DoD)
Дууссан story бүр ямар байх ёстойг тохирсон багийн гэрээ. Хувилбарын хяналтад хадгална.
«Бэлэн»-ий тодорхойлолтDefinition of Ready (DoR)
Story-г спринтэд авахаас өмнө хангасан байх шаардлага: INVEST, шалгуур, шошго, ярилцлага.
Санаатай алдаа оруулахFault injection
Системийн нэг хэсгийг санаатайгаар унагаж, систем бүхэлдээ тогтвортой үлдэж байгааг шалгах тест.
Функцийн унтраалгаFeature flag
Эрсдэлтэй функцийг ажиллаж байх үед нь асааж, унтраах тохиргоо. Анхдагчаар унтраалттай.
Fixturepytest fixture
Хэд хэдэн тестэд хэрэгтэй төлөвийг (жишээ нь өгөгдлийн сан) бэлтгэдэг pytest туслах функц.
INVESTIndependent · Negotiable · Valuable · Estimable · Small · Testable
Сайн user story-ийн шинж: бие даасан, ярилцаж болох, үнэ цэнтэй, үнэлж болох, жижиг, тестлэж болох.
Мутацын тестMutation testing
Кодыг бага зэрэг өөрчилж, тестүүд тэр өөрчлөлтийг илрүүлж байгаа эсэхийг шалгах арга. Амьд үлдсэн мутант = сул тест.
Функциональ бус шаардлагаNon-functional requirement (NFR)
Систем юу хийхийг бус, хэрхэн ажиллахыг тодорхойлох шаардлага: хурд, аюулгүй байдал, нууцлал г.м.
Нэгтгэх хүсэлтPull request / Merge request
Кодын өөрчлөлтийг хянуулж, үндсэн branch-д нэгтгэх хүсэлт. Кодын овоолго биш — яриа.
RunbookRunbook
Систем асуудалтай үед юу хийхийг бичсэн нэг хуудас заавар: нэвтрэх, дахин эхлүүлэх, буцаах, лог унших.
Smoke тестSmoke test
Систем асаж, үндсэн зам хариу өгч байгааг шалгах хамгийн бага тест.
СпринтSprint
Баг тодорхой хэмжээний ажлыг гүйцэтгэдэг богино, тогтмол хугацаа (ихэвчлэн 1–2 долоо хоног).
МөрдөлтTracing
Алдааг дуудлагуудын дундуур мөрдөхөд хангалттай контекст бүртгэх. Алдааны лог бүр request ID агуулна.
Хэрэглэгчийн түүхUser story
«As a …, I want …, so that …» хэлбэрээр бичсэн хэрэглэгчийн хэрэгцээ.
Гүйцэтгэж буй ажлын хязгаарWIP limit
Kanban-ы нэг баганад нэгэн зэрэг байж болох картын дээд тоо. Квот биш, далд дарааллыг илрүүлэх оношлогоо.

質問 Асуулт хариулт

Түгээмэл асуулт

Энэ хуудас хичээлийн албан ёсны хөтөлбөр мөн үү?

Үгүй. Энэ хуудас хичээлийн агуулгыг ойлгох, бие даан давтахад туслах зорилготой. Хичээлийн хуваарь, дүн, даалгавар илгээх зэрэг албан ёсны мэдээллийг их сургуулийн мэдээллийн системээс харна уу.

Ямар програмчлалын хэл ашигладаг вэ?

Python 3.11 ба түүнээс дээш хувилбар. Тест бичихэд pytest, хувилбарын хяналтад Git ба GitLab, орчноо ажиллуулахад Docker ашиглана.

Урьдчилан юу мэдэх хэрэгтэй вэ?

Python-ы үндсэн мэдлэг (хувьсагч, функц, класс) хангалттай. Git, Docker, тест, CI зэргийг хичээлийн явцад алхам алхмаар заана. 1-р долоо хоногийн лабораторийн ажлаас эхлээрэй.

Хичээлийн материал ямар хэл дээр байдаг вэ?

Хичээл англи хэл дээр явагддаг тул лекц, дасгал, лабораторийн материал англи хэл дээр байна. Энэ хуудасны нэр томьёоны тольд гол ойлголтуудын монгол тайлбар бий.

Ганцаараа хийх үү, багаар хийх үү?

Заавар өөрөөр заагаагүй бол лабораторийн ажлыг ганцаараа хийнэ. Зарим хэсэгт (жишээ нь хос хяналт) өөр оюутантай хамтарна. 1–2 хүний суралцах бүлэг байгуулж болно, гэхдээ заавал биш.

Хичээл тасалсан эсвэл хоцорсон бол яах вэ?

Долоо хоног бүр өмнөх долоо хоногийн ажил дээр суурилдаг. Тиймээс:

  1. Тасалсан долоо хоногийнхоо төлөвлөгөөг нээж, унших материалыг гүйлгэж уншина.
  2. Тэр долоо хоногийн лабораторийн ажлыг эхэлж хийнэ — дараагийн долоо хоногууд үүн дээр тулгуурладаг.
  3. Дараа нь одоогийн долоо хоног руугаа шилжиж, явцаа «Дууссан» тэмдэглэгээгээр хянана.

Хоёр долоо хоногоос дээш нэг асуудал дээр гацсан бол лабораторийн цагаар заавал асуугаарай.

ChatGPT зэрэг хиймэл оюун ашиглаж болох уу?

Болно, гэхдээ гурван алхамт дүрмийг мөрдөнө: зориуд ашиглах, үр дүнг шалгах, ямар хэрэгсэл, ямар prompt ашиглаж, юуг шалгаснаа баримтжуулах. Prompt-оо тэмдэглээгүй бол тухайн алхмаа дахин хийж баримтжуулахыг шаардаж болно.

Хичээлд бүртгэлгүй ч бие даан судалж болох уу?

Болно. Төлөвлөгөөг 1-р долоо хоногоос дарааллаар нь дагаж, өөрийн жижиг төслийг эхнээс нь хийж үзээрэй. Хоёр үндсэн номыг хамт уншихыг зөвлөж байна.

Асуулт гарвал хэнд хандах вэ?

Лабораторийн цагаар асуух эсвэл холбоо барих хэсэгт буй хаягаар холбогдоорой.
